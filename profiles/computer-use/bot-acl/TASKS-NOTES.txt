Bot task implementation verification

Scope: default profile plugin /home/shi/.hermes/plugins/bot-acl.
The coding profile has a separate older plugin; it is deliberately unchanged.

bot_task actions: spawn, list, status, wait, steer, stop.
spawn admits a task and returns without waiting for child readiness. A bounded
startup thread retains the caller's contextvars. New sessions only; no user-
supplied session ID, no Bot Chat resume, no restart recovery. wait waits for a
completion event for at most two seconds before requesting session state (RPC
itself has a separate maximum 30-second timeout). stop kills/reaps the dedicated
child process group and suppresses subsequent work; effects already performed
cannot be rolled back. Existing same-group ACL and parent ownership apply.

Transport: the installed official TUI's tui_gateway.entry stdio JSON-RPC
subprocess, session.create, prompt.submit, session.steer, session.activate.
No HTTP API listener or shared gateway changes. No private function imports
were added. The module entrypoint is shipped by Hermes; a stable documented
third-party compatibility guarantee has NOT been established. Runtime discovery
is used and missing entrypoint fails closed, without another transport resend.

Important capability boundary:
The installed TUI backend owns pending_steer replay in
_run_post_turn_followups. The plugin never duplicates that replay. The public
stdio results do not expose pending_steer plus a definitive drained/final marker,
so the plugin CANNOT certify exactly-once replay or finality. message.complete
can precede another automatic turn. Status includes finality_verified=false;
observed completed can return to running. The child is not killed on the first
complete event, preventing premature loss of backend-owned replay. It remains
bounded by its timer or explicit stop. A stop racing with a follow-up that has
already begun cannot retroactively prevent that execution.

No claim is made that accepted guidance was consumed at a live tool boundary.
The returned backend result is preserved. No automatic resend is attempted.
A model-driven end-to-end steering/replay test was not performed; the real
subprocess smoke test only verifies readiness and capabilities RPC in a
temporary empty profile, with no model invocation.
